# 大型剧情检索：Rerank 输入规模消融报告

日期：2026-08-30

## 1. 实验问题

64 个 Episode 的 evidence rerank 在上一轮 9 次冷查询中平均占 24.743 秒和整条管线的 57.2%。本轮验证：

1. 将预压缩上限降低到 48、32、24 后，三道多跳题是否仍能完整召回必需事实槽；
2. 输入规模缩减能否稳定降低 API 延迟；
3. 是否可以在不依赖增长边数量作为评测指标的前提下调整默认配置。

## 2. 方法

固定使用 `experiments/manifests/foreground_benchmark_v1.json`：

- 补习部表象与真正政治目的；
- 乐园悖论、渚与未花；
- 古圣堂袭击、阿里乌斯与未花的因果链。

每道题含 3 个必须回答的事实槽。一次完整重复包含三道题、9 个事实槽。

实验分两阶段：

1. 48、32、24 并行筛选，各运行一次完整三题；
2. 最小通过候选 24 单进程串行补两次，和筛选轮合并为每题 3 次、共 27 个事实槽。

并行筛选只用于可靠性排除和粗略观测，不能与串行基线直接比较延迟。最终性能比较使用 64 输入串行基线与
24 输入串行确认轮。

## 3. 筛选结果

| 配置上限 | 查询通过 | 事实槽 | 平均总耗时 | 平均 rerank |
|---:|---:|---:|---:|---:|
| 48 | 3/3 | 9/9 | 44.404 s | 25.826 s |
| 32 | 3/3 | 9/9 | 40.450 s | 22.689 s |
| 24 | 3/3 | 9/9 | 47.406 s | 26.140 s |

三组在并发 API 条件下都完整召回。24 比 32 慢说明服务端调度、模型输出和问题难度造成的噪声大于单次
输入缩减收益，因此不能用一次均值选择配置。

报告位置：

- `logs/rerank-ablation/limit32-screen-v1/20260830T045419.913558Z/report.json`
- `logs/rerank-ablation/limit24-screen-v1/20260830T045439.245000Z/report.json`

## 4. 24 输入确认结果

确认轮报告：

`logs/rerank-ablation/limit24-confirm-v1/20260830T045908.836993Z/report.json`

- 6/6 查询通过；
- 18/18 事实槽命中；
- 平均总耗时 41.892 秒；
- 最小 20.480 秒；
- 最大 57.430 秒；
- evidence rerank 平均 24.816 秒。

与筛选轮合并后，24 配置共 9/9 查询通过、27/27 必需事实槽命中。

## 5. 与 64 输入串行基线对比

| 指标 | 64 基线 | 24 确认 | 变化 |
|---|---:|---:|---:|
| 事实槽 recall | 27/27 | 18/18（合并后 27/27） | 均为 100% |
| 平均总耗时 | 43.258 s | 41.892 s | -3.2% |
| 平均 rerank 耗时 | 24.743 s | 24.816 s | 基本不变 |
| 平均 rerank 输入 Episode | 64.0 | 30.0 | -53.1% |
| 平均候选文本字符 | 4611.3 | 2224.3 | -51.8% |
| 平均相关提示字符 | 26453.4 | 13103.3 | -50.5% |

配置值 24 是软预算，不是无条件硬截断。预压缩器会保护查询各语义分支的 evidence floor；必要时有效输入
可以超过 24，本次平均为 30。这也是远距离因果题没有因机械截断而丢失关键证据的重要原因。

## 6. 结论

24 输入已经证明能在当前固定多跳集上保持完整召回，并把 rerank 上下文约减半，因此具有明确的 token、
网络传输和上下文占用收益。但 evidence rerank 延迟没有同步下降，说明当前耗时主要受模型生成、服务端排队
或固定提示处理影响，而不是简单与候选字符数线性相关。

因此本轮决策是：

- 前台默认 `MEMORY_FOREGROUND_RERANK_PRECOMPRESSION_LIMIT` 从 64 改为 24；
- 后台深度流程继续使用 100，不受影响；
- 保留环境变量，可立即回退到 32 或 64；
- 不宣称 24 已在未知问题上取得普遍最优，只确认当前 3 题 × 3 次没有召回损失。

## 7. 下一步

下一轮不应继续只缩候选数量，而应定位模型调用本身：

1. 为核心记忆引擎的 intent 与 rerank API 记录输入 token、输出 token、reasoning token、正文长度、模型名和
   服务端 usage；
2. 使用相同候选和固定提示，比较 DeepSeek-V3.2 与 Qwen3.5-9B thinking off 的 rerank 正确率和 P50/P90；
3. 单独优化 intent parse。它在 64 基线平均 11.785 秒、P90 25.577 秒，是第二大瓶颈；
4. 将测试集扩展后再确认 24，尤其加入目标证据在初始候选 50–100 名之间的长尾问题；
5. 如果更大集合出现漏召回，优先回退到 32，而不是削弱 evidence floor 保护。
