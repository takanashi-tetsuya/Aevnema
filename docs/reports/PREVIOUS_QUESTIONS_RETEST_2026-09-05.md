# 旧剧情问题复测报告（2026-09-05）

## 结论

当前记忆系统还不能稳定回答此前的三道深度剧情问题。

- 题 1：部分回答。找到了补课部的表面理由和政治目的，但没有稳定给出“叛徒”这一身份结论。
- 题 2：失败。知识检索和自动升级进入 deep 后，回答阶段因模型任务超时，没有返回答案。
- 题 3：部分回答。找到了阿里乌斯直接袭击古圣堂，但没有确认未花此前向阿里乌斯提供支援的因果链。

这不是“知识库没有相关内容”。三题所需的 9 个事实槽对应的 30 个 Episode ID 均存在于当前知识库。主要问题是远距离、多事实问题在候选压缩和最终选择时没有保持每个事实槽的证据；此外 chat 生成阶段的超时会进一步放大失败。

## 测试范围与隔离

本次使用当前的人类可读蔚蓝档案知识库副本，不使用旧版评测清单中的 Episode ID。测试清单为：

`experiments/manifests/previous_questions_current_kb_20260905.json`

该清单包含 3 道问题、9 个事实槽和 30 个候选 Episode，并已通过完整性校验：无缺失 ID、无空事实槽、无 source 越界。所有真实请求均指向临时 SQLite 副本；正式知识库没有写入。

当前副本的主要规模为：约 4,017 个 Source、7,019 个 Paragraph、约 13,764 个 Episode、约 10,675 个 Concept、约 42,689 条 Association。测试使用 float32 embedding、BGE reranker 配置，未启用 contextual association，也关闭了本轮测试的后台增长，以便只观察现有检索和回答能力。

## A. 检索层复测（只检索，不生成答案）

### 自动路由 / standard 起步

三题均由标准档开始；证据不足时，其中的知识域会自动升级为 deep。结果如下：

| 指标 | 结果 |
|---|---:|
| 事实槽总数 | 9 |
| 找到的事实槽 | 5 |
| fact-slot recall | 55.6% |
| 平均耗时 | 32.462 秒 |
| 最短 / 最长 | 28.581 / 36.529 秒 |

逐题情况：

1. **补课部表象与真相**：3 个槽命中 2 个。找到了 Episode 22、257 等百科/篇章总结，未保留能直接支持“成员中藏有阻止条约的叛徒”的台词证据（如 3133、3181、3487）。
2. **乐园悖论与信任危机**：3 个槽命中 1 个。保留了 3573 的“乐园悖论”，但丢失了渚的排查行动和未花政变证据。
3. **古圣堂袭击因果链**：3 个槽命中 2 个。保留了 3723，可支持爆炸位置和阿里乌斯相关线索，但未保留未花支援阿里乌斯的 3924/4052 等证据。

自动路由的实际知识域结果显示：三题的 `retrieval_intensity` 最终均为 `deep`，而 deep 的默认重排后端是 LLM。也就是说，standard 的初筛没有覆盖全部事实槽，升级本身没有自动补回缺失槽位。

### 强制 deep 对照

| 指标 | 结果 |
|---|---:|
| 事实槽总数 | 9 |
| 找到的事实槽 | 2 |
| fact-slot recall | 22.2% |
| 平均耗时 | 29.437 秒 |
| 30 秒 deadline 超时 | 2 / 3 |

强制 deep 并没有改善这组问题：前两题在 30 秒 deadline 内超时，第三题仍只保留爆炸和阿里乌斯相关证据。说明“把档位切到 deep”不是覆盖保证；缺少事实槽级别的覆盖选择时，deep 只是增加规划和重排成本。

## B. 完整回答链路复测

完整链路包括：记忆检索、证据整理、chat 模型生成。测试使用独立会话，避免前一题的对话历史污染后一题。

| 题目 | 路由 | 总耗时 | 结果 |
|---|---|---:|---|
| 补课部表象与真相 | standard → knowledge deep | 35.859 秒 | 部分回答 |
| 乐园悖论与信任危机 | standard → knowledge deep | 44.761 秒 | 生成超时 |
| 古圣堂袭击因果链 | standard → knowledge deep | 35.074 秒 | 部分回答 |

### 题 1

模型正确复述了补课部由特别考试/补习组成、表面目标是避免退学，并提到渚借此寻找潜在叛徒。但回答在“补课部里藏着什么身份的人”处没有完成结论，停留在反问/未完成状态。

检索质量记录为：`entity_coverage=0.667`、`claim_slot_coverage=0.533`、`sufficient=false`。这与最终文本缺少叛徒身份相符。

### 题 2

知识检索阶段未报告错误，但回答生成阶段首选和备用 chat 模型均在 20 秒任务 deadline 内超时，最终没有用户可见答案。

此处至少叠加了两类延迟：

- 记忆检索约 22.064 秒；
- chat 首选模型超时后继续尝试备用模型，导致总耗时达到 44.761 秒。

因此题 2 的失败不是知识库缺失，也不是回答内容被审计器拒绝，而是生成链路的 deadline/fallback 组合造成的超时。

### 题 3

模型正确指出明面上的袭击者是阿里乌斯势力，并能说明古圣堂爆炸与阿里乌斯潜入有关；但对“哪位茶会高层此前暗中协助”给出“当前证据不足，无法确认”的回答。

这是一个合理但不完整的保守回答：当前最终证据没有带上 3924（未花亲手向阿里乌斯提供补给、寻求其支持）等关联，因此模型无法完成要求的第二跳。知识库实际包含该证据，问题在检索覆盖而非事实不存在。

## 失败分类

### 1. 不是语料缺失

当前库明确包含下列关键证据：

- 3131、3133、3181、3332：渚建立补课部、寻找叛徒和监视嫌疑人的目的；
- 3487：花子与梓被识别为叛徒/棋子线索；
- 3573、3575、3751：乐园悖论及其关于真心/信任的隐喻；
- 3519、3520、3521、3522：未花与阿里乌斯交易、政变及政治目标；
- 3656、3687、3723、3902、3906：古圣堂爆炸、导弹和阿里乌斯潜入；
- 3924、4002、4052：未花向阿里乌斯提供补给或寻求其支持，以及事后关系。

### 2. 事实槽覆盖不足

当前候选池仍偏向高相似度的百科/篇章摘要（例如 22、116、121、126、257），而非同时保留每个原子事实槽的主线台词。对于“动机 + 行动 + 参与者 + 后续因果”问题，单纯按整体问题相似度或 reranker Top-N 不够。

### 3. 自动升级没有形成闭环

检索质量已经报告 `sufficient=false`，但升级后的 deep 查询没有把缺失槽转化为硬性补充查询，也没有在最终选择阶段强制每个槽至少保留一条证据。因此升级增加了 API 调用，却没有稳定增加覆盖。

### 4. 生成 deadline 与 fallback 叠加

chat 任务的 20 秒 deadline 是按模型尝试计算的；首选超时后，备用模型再次占用一个近似窗口。对需要 15–20 秒检索的剧情问题，这会使单题总耗时超过 40 秒，并可能在回答尚未开始时耗尽用户等待时间。

## 下一步改进建议

本次没有修改正式数据库或生产配置。建议按以下顺序修复并重新验收：

1. **事实槽级覆盖选择器**：将原子查询/事实槽变成选择约束。最终证据至少为每个槽保留一条候选，再按相关性补足其余候选；不能让百科摘要挤掉主线台词。
2. **缺槽驱动 follow-up**：`sufficient=false` 时，只为未覆盖槽生成补充查询，例如“渚为何组建补课部”“未花向阿里乌斯提供了什么”“政变目标是什么”，而不是再次发送整句长问题。
3. **回答上下文改为事实契约**：给 chat 模型发送精简的“主张—证据 ID—证据文本”块，并明确哪些槽已覆盖、哪些未覆盖；不要让模型从一堆未分组的候选文本自行猜测。
4. **回答 deadline 独立于检索 deadline**：检索结束后为生成预留明确时间；若首选模型超时，缩短备用模型预算或直接返回已审核的证据型回答，避免两个 20 秒窗口串联。
5. **继续保留当前评测清单**：旧版 Episode ID 已证明会随知识库重建而失效，今后每次导入/重建后应重新验证 manifest，再进行质量判断。

## 最终判定

**当前版本：不通过三题完整回答验收。**

系统已经能够从当前蔚蓝档案知识库检索到部分远距离证据，也能在证据不足时表现出一定的谨慎；但尚未达到“跨多个剧情碎片完成闭环因果回答”的目标。下一轮应优先修复事实槽覆盖和回答 deadline，而不是继续增加模型提示词或单纯提高 deep 档预算。
