# 两次白子对话失败诊断与修复报告

日期：2026-09-01

## 结论

两次失败不是同一种原因。

1. “你还记得为师当时怎么和白子相遇的吗”同时存在架构缺陷和知识缺口。旧路由没有查询剧情库；即使强制查询剧情库，当前数据库也没有“老师与白子初遇”的事件证据。
2. “那你记得白子的哪些事情呢”主要是架构缺陷。剧情库已有足够的白子资料，但旧路由完全没有调用剧情库，回答模型随后凭自身参数补出了“薯片”等无证据内容。

## 日志证据

两轮请求位于 `logs/2026-09-01.log` 的 117—150 行附近。

- 第一轮系统上下文只有“当前用户的私人记忆”，明确显示私人 Episode 无命中，没有“外部剧情知识库”区段。
- 第二轮同样只有私人记忆区段。初稿虚构白子喜欢薯片；第一次私人记忆审计虽然拒绝了该回答，但重写稿仍保留了没有剧情证据支持的耳机等描述，第二次审计错误通过。
- 当时的审计提示明确声明“不评价一般作品知识”，所以它只能阻止私人共同经历越界，不能阻止剧情事实幻觉。

## 根因

### 1. 私人标记遮蔽剧情意图

`你记得`、`还记得` 被列为私人记忆标记。旧路由只要检测到这些标记，又没有出现“剧情、主线、学园”等显式关键词，就固定选择：

```text
user=true
public=true
knowledge=false
```

这把“你记得某个角色的哪些事情”错误等同为“你记得当前用户的哪些事情”。

### 2. 同一查询文本直接送入不同域

私人域和剧情域需要不同的查询视图。对私人域，“你还记得”是重要意图；对剧情域，这个外壳会让规划器误判为 `private_memory_evidence`，并可能漏掉角色实体。

### 3. 小库快速规划器写死回答形状

小型数据库快速路径原先给所有标准检索统一设置：

```text
answer_shape=private_memory_evidence
```

剧情域也被错误标记为私人证据任务。

### 4. 回答审计只保护私人事实

旧审计器不逐项核对作品知识。即使一句话中只有一部分有证据，它也可能把整句当成已支持事实。

## 已完成的通用修复

修复没有加入白子、阿拜多斯或本次剧情专用规则。

1. 增加通用角色/实体问句识别：支持“记得 X 的哪些事情”“和 X 相遇/见面/认识”等表达。
2. 对同时具有私人回忆措辞和外部实体的问句启用混合域路由：私人、公共、剧情三域并行检索，结果仍保持域隔离。
3. 为剧情域生成独立查询视图：删除“你还记得”等会污染剧情规划的会话外壳，但原始用户消息保持不变。
4. 快速规划器按域设置回答形状：用户域为 `private_memory_evidence`，剧情域为 `lore_evidence`，公共域为 `shared_memory_evidence`。
5. 扩展现有审计而不增加一次固定模型调用：在原本就会执行的记忆审计中，强制将每个剧情主张原子化，并为每项列出直接支持的证据 ID。任一项没有证据 ID，整次审计失败并触发自然角色口吻重写。

## 验证结果

- `tests.test_memory_integration`：58 项测试全部通过。
- 第一问强制剧情检索：能识别实体“白子”，但没有命中初遇事件；数据库全文搜索中，同时包含白子与“相遇/初遇/见面/认识”的 Episode 数为 0。
- 第二问最终自动路由：`personal_and_entity_lore`，三域开启，知识域目标实体为“白子”，回答形状为 `lore_evidence`。
- 第二问剧情 Top 5：白子的对策委员会身份、寡言直接、喜爱运动、银行主题、好感剧情范围，均来自现有 Episode。
- 真实模型审计探针：能够拒绝“老师在沙漠救下白子”的虚构初遇；能够把“成员身份、喜欢运动、喜欢薯片”拆成三项，只保留前两项，并删除没有证据 ID 的“喜欢薯片”。

## 对导入资料的最低要求

如果希望支持“某两人第一次如何相遇”这类问题，只有人物百科和章节摘要不够。导入资料至少需要满足：

1. 含有该事件本身，而不只是“后来逐渐建立信任”的结果概括。
2. 分片中同时保留参与者、动作和必要上下文，不能把人物名与事件动作切到不同 Source。
3. 能区分故事发生顺序与文件叙述顺序，倒叙也必须可还原实际先后。
4. Source 足够短以便回读证据，但不能短到失去代词指向与事件因果。
5. Episode 必须自包含，避免只写“她在那里遇见了他”。
6. 对文本没有提供的细节明确标为未知，不允许导入模型用常识补全。
