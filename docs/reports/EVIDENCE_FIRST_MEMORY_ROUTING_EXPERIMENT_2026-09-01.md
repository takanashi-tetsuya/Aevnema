# 证据驱动记忆路由实验报告

日期：2026-09-01

## 1. 实验问题

当前机器人使用一组同步启发式规则，在检索前判断请求应该进入私人、公共或剧情知识域，并进一步选择 light、standard 或 deep。此前为修复自然角色扮演问法，又增加了去除“你还记得”等对话外壳、抽取人物、识别关系和因果表达的规则。

这些规则能修复已知样本，但存在结构性缺陷：

1. 自然语言表达近乎无限，规则覆盖率无法靠持续追加枚举获得。
2. 一个句式可能同时指向私人经历、公共印象和外部剧情知识。
3. 检索前尚未看到证据，却提前决定唯一域和推理强度，容易把不确定性伪装成确定分类。
4. 新规则会互相干扰。本轮中，“凯撒集团和阿拜多斯有什么纠葛”曾被抽成一个额外的复合伪实体；关系证据已经被 BGE 高分命中，却又被机械的候选保底槽判为未覆盖。
5. 将越来越多自然语言知识写进路由代码，会把系统逐步变成专家系统，降低模型根据上下文自由判断的能力。

本轮目标不是继续补句式，而是验证能否把流程改为“先取真实候选，再由模型判断证据是否有用”。

## 2. 名词定义

### 2.1 专家系统式路由

程序员预先列出关键词、正则表达式和条件分支，并把每种表达映射到固定动作。例如见到某个关系词就进入 deep，或见到某种回忆式开头就同时查询固定域。它可解释、便宜，但语言覆盖会随规则数量增长而变得脆弱。

### 2.2 模型驱动路由

由语言模型或语义模型根据完整请求、对话上下文和可用数据库目录生成检索计划。程序只校验结构、权限和预算，不解释具体剧情或具体句式。

### 2.3 证据驱动升级

不在检索前猜测任务一定复杂。先用低成本方式获取候选，然后依据候选是否覆盖实体、事实槽、时间、因果和冲突，再决定是否扩大候选、进行图遍历、调用生成式规划器或进入 deep。

### 2.4 Probe

一个只用于判断“当前域是否可能存在可用证据”的最小检索请求。本轮 probe 使用原始问题、float32 embedding、无图遍历、无 follow-up、小候选预算；BGE 版本再对候选执行一次 cross-encoder 重排。

### 2.5 Cross-encoder reranker

它同时读取 query 与一条候选文本，直接估计二者相关性。与 embedding 的双塔向量相似度相比，它较慢但能更准确处理关系、否定和上下文。当前模型为 `Pro/BAAI/bge-reranker-v2-m3`。

### 2.6 MemoryDomainCatalog

从数据库当前内容自动派生的域目录，包括各域规模、knowledge 来源概况、代表性 Concept 和语言。它用于告诉规划模型“系统实际有什么”，而不是写死某一作品或人物规则。更换知识库后目录应自动变化。

### 2.7 Agentic follow-up

回答模型在看过第一阶段证据后，如果发现某个原子事实仍缺失，不直接编造或仅返回失败，而是输出结构化的第二阶段检索请求。系统执行补充检索后再次生成答案。复杂度由模型基于证据决定，而不是由输入关键词预判。

## 3. 基础性能问题与修复

### 3.1 原始现象

自然问法基线在路由修复后可达到 `recall@20 = 100%`，但 light 平均约 8.64 秒，standard 平均约 10.71 秒。阶段计时显示 `final_selection` 单独消耗约 5–7 秒。

### 3.2 根因

最终选择会对多个 Episode 逐个读取 Association 邻接边，时间线排序又会逐个读取一次。每次仓库读取都会建立新的 SQLite connection。在 WSL 通过 `/mnt/c` 访问数据库时，连接与文件系统往返开销被显著放大，形成 N+1 查询。

### 3.3 修复

记忆引擎新增 `AssociationRepository.neighbors_many()`，一次读取多个同类型节点的邻接边；只读和 staged Association overlay 同步支持批量接口。late learned bridge closure 与 chronology 优先使用批量读取，对旧测试桩保留逐个读取 fallback。

同时修复请求级 `RetrievalPlan.candidate_limit` 只影响 rerank 预压缩、却没有真正写入 `retrieval.candidate_limit` 的遗漏。

### 3.4 结果

在相同自然问法与相同真实模型下：

| 配置 | recall@20 | 平均耗时 | 最大耗时 | 5 秒内比例 |
|---|---:|---:|---:|---:|
| light，修复前 | 100% | 8.64 s | 9.13 s | 0% |
| standard，修复前 | 100% | 10.71 s | 11.64 s | 0% |
| light，批量邻接后 | 100% | 3.66 s | 4.02 s | 100% |
| standard，批量邻接后 | 100% | 4.87 s | 5.12 s | 66.7% |

`final_selection` 降至约 0.30–0.45 秒。该优化不改变检索语义。

## 4. 路由方案对比实验

### 4.1 每条请求前置生成式 JSON 规划

规划器输出 private/public/knowledge、各域 query、实体、关系、时间、因果、答案槽、强度和写入策略。提示词不包含具体人物或剧情。

| 模型/条件 | 通过率 | 平均耗时 | 最大耗时 |
|---|---:|---:|---:|
| Qwen 9B，无数据库目录 | 5/12，41.7% | 4.61 s | 7.25 s |
| Qwen 35B，无数据库目录 | 6/12，50.0% | 19.67 s | 68.92 s |
| DeepSeek V3.2，无数据库目录 | 7/12，58.3% | 15.58 s | 26.80 s |
| Qwen 9B，自动数据库目录 + 真实实体 | 9/12，75.0% | 8.10 s | 33.13 s |

结论：

- 完整生成式规划可作为困难请求的第二阶段，但不适合作为每条消息的同步前置步骤。
- 更强模型没有自动获得稳定、低延迟路由。
- 数据库目录显著改善 knowledge 识别，证明模型必须知道当前库中实际有什么。
- 规划器不应被要求在证据出现前一次性决定 creative。比如“刚刚谁发消息”应先查询私人事实；查不到后才允许转为创造性角色扮演，并用 knowledge 选择合适角色。

### 4.2 Embedding 域原型

把请求 embedding 与 private/public/knowledge/none/creative 的多语言描述比较。

结果：能识别部分明显私人、公共和资料问题，但相似度不是分类概率。“补课部为什么成立”甚至更接近 creative 描述；寒暄与各记忆域也具有较高相似度。不能用固定阈值可靠分域。

### 4.3 用 reranker 对域定义排序

将五个域定义当作候选文档交给 BGE reranker。平均仅 0.63 秒，但相关性模型不等于自然语言推理分类器。域定义中的否定和元语言会导致低分、反向排序，仍不适合直接承担路由。

### 4.4 直接读取索引最高相似度

对请求做一次 embedding，然后读取当前 knowledge Episode/Concept 索引的 Top-5。

真实知识问题与非知识问题的最高 cosine 大量重叠：约 0.43–0.71 对 0.45–0.52。大型库总能找到泛化近邻，因此最高向量分数不能证明证据可用于回答。

## 5. 最有效方案：Probe + BGE

### 5.1 无图 probe

参数：

- 使用原始自然问法；
- 不做句式解析；
- `graph_hops = 0`；
- `candidate_limit = 20`；
- 无 follow-up；
- 无 reranker；
- 最终保留 12 个 Episode。

结果：5 个有 gold 的剧情自然问法 `recall@20 = 100%`，平均 1.47 秒，最大 1.60 秒。

### 5.2 Probe + BGE

在相同候选上加入 BGE cross-encoder：

| 指标 | 结果 |
|---|---:|
| recall@20 | 100% |
| 平均耗时 | 2.26 s |
| 最大耗时 | 2.48 s |

头部证据也明显改善：

- 白子 Terror 差异：0.87；
- 星野对梦前辈自责：0.98；
- 渚组织补课部：0.98；
- 凯撒与阿拜多斯：0.91；
- 宽泛白子人物资料：0.16。

而当前 knowledge 中没有直接证据或本就不应从剧情库回答的样本为：

- 老师与白子的初次相遇：0.01；
- 私人暗号：0.00；
- 私人饮料偏好：0.00；
- 全用户公共约定：0.00；
- 早上好：0.01；
- 创造“刚刚收到的学生消息”：0.01。

在当前 11 个样本上，`0.05` 可以完整分开“knowledge 有可用于当前回答的证据”和“只是找到了弱近邻”。这只是下一轮扩大校准的候选阈值，不能直接宣称为通用常数。

## 6. 推荐的新架构

```text
当前消息 + 必要的最近对话
              │
              ▼
       三域并行最小 probe
       private / public / knowledge
              │
              ▼
        各域小候选 BGE 重排
              │
              ▼
    按真实证据相关性保留或抑制域
              │
              ▼
       回答模型检查原子事实覆盖
          │                 │
       已覆盖             缺槽/冲突
          │                 │
       直接回答      生成结构化 follow-up
                            │
                            ▼
                  standard/deep 检索计划
                  图扩展、时间线、LLM coverage
                            │
                            ▼
                         再生成答案
```

关键原则：

1. 宽进严出：初始阶段允许多域候选，最终只暴露实际相关证据。
2. 域隔离不等于域互斥：数据库仍严格分开，但一次请求可以并行查询多个域。
3. 可信度与相关性分离：Episode 的 provenance/confidence/generation 表示事实可信与推断距离；BGE 分数表示“对当前问题是否有用”。
4. creative 后判定：先查真实私人事件；不存在时，回答模型才创造新事件，写入私人域，不污染剧情库。
5. deep 后判定：除非用户显式选择固定 deep 模式，否则主要由第一阶段证据缺槽、冲突、多跳依赖触发。
6. 程序只执行结构化计划、预算、权限和证据契约，不解释具体人物、地点或剧情句式。

## 7. 当前代码状态

已经进入主实现的改动：

- SQLite Association 批量邻接读取；
- chronology 与 late bridge closure 的 N+1 修复；
- 请求级 candidate limit 正确写入检索引擎；
- RetrievalQuality 可记录模型产生的语义约束覆盖；
- 本轮新增的“相遇/关系/因果”快速句式规则已回退，没有进入主路径。

仍处于实验隔离、尚未替换生产路由的内容：

- 生成式 `MemoryIntentPlanner`；
- `MemoryDomainCatalog` 实验；
- embedding 域原型；
- reranker 域定义分类；
- probe 与 probe+BGE 实验脚本；
- 0.05 候选门槛。

当前生产路径仍保留早期的 `route_memory_query()`、`_lightweight_target_entities()` 和 `_knowledge_retrieval_question()`。它们用于维持现有机器人行为，没有在本轮仓促删除。下一阶段应在 evidence-first 路径通过扩大样本和端到端回答测试后，再逐步将这些函数降级为异常 fallback，最终删除大部分语言枚举。

## 8. 下一阶段验收方案

### 阶段 A：扩大阈值校准

至少准备 100–200 条请求，平衡以下类别：

- 直接人物事实；
- 宽泛人物评价；
- 关系、时间、因果、多跳；
- 知识库确实缺失的同实体问题；
- 纯私人回忆；
- 公共记忆；
- 闲聊；
- 创造性角色扮演；
- 中英日及混合语言；
- 带上文的代词、省略和反问。

报告 ROC/PR、false accept、false reject，并按 query 类型观察 BGE 分数分布。阈值应配置化，并允许“灰区”进入回答模型或规划器复核。

### 阶段 B：跨域 probe

对 private/public/knowledge 使用同一请求级 probe plan 并发查询，合并候选时保留域标签、数据库 ID、source_id、provenance、confidence 和 generation。验证用户隔离没有被破坏。

### 阶段 C：回答模型 follow-up 协议

回答模型必须在两种输出间选择：

1. 证据足够：输出最终角色化回答及命题分流候选；
2. 证据不足但可继续搜索：输出结构化 follow-up，包含缺失原子事实槽、补充 query、目标域和建议强度。

程序只验证 schema 和预算，不解析自然语言剧情。

### 阶段 D：端到端角色扮演

同时测：

- 简单事实首次响应时间；
- 缺失事实是否自然承认未知；
- 创造事件是否只进入私人域；
- 好的推测是否以 generation > 0 和证据 ID 写入合适域；
- deep 多跳问题是否在需要时自动升级；
- 静态规则关闭前后答案质量与延迟差异。

### 阶段 E：逐步移除旧路由

先让新旧路由 shadow-run，只记录决策差异；达到约定的域召回、错误率和延迟后，将旧规则降级为模型/API失败时的保守 fallback。最后再删除具体句式和作品词表。

## 10. 当前结论

本轮最重要的结论不是“换一个更强的路由模型”，而是调整决策时机：

> 在没有证据前，让任何模型一次性判断完整域和完整推理计划都不够稳定；先用廉价高召回 probe 看到真实候选，再让 BGE 与回答模型判断相关性，才是更通用的路线。

这条路线既保留模型推理能力，又把耗时控制在约 2.3 秒的记忆第一阶段，并为复杂请求留下真正按证据触发的 standard/deep 升级空间。
