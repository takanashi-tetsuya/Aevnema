# 记忆系统下一阶段测试报告（2026-08-29）

## 1. 测试范围

本轮同时验证两类能力：

1. 蔚蓝档案剧情库的跨文件、多跳证据召回；
2. 聊天机器人中的私人用户域、公共域和外部剧情知识域隔离。

剧情库测试基线为 736 个 Source、4073 个 Episode、2970 个 Concept、8904 条 Association。Embedding 维度为 1024，SQLite 与 RAM 均使用 float32。

## 2. 专有名词

- **Candidate@100**：基础向量、稀疏文本和图遍历合并后，交给 LLM 精排的 100 个候选 Episode。关键证据若未进入这里，后续模型无法补救。
- **Rerank Top-30**：LLM 从 Candidate@100 中按问题的各证据槽选择的 30 个 Episode。
- **约束型子问题**：询问“真正原因、真实身份、暗中协助、因果、幕后关系”等不能由表面相似词替代的问题。
- **候选保留席位**：只保证约束型子问题的若干候选进入 Candidate@100，不保证进入最终证据，也不提高其可信度。
- **generation**：Association 距离直接 Episode 证据的推断代数。generation=0 为直接抽取关系，更大的数字表示推断链更远。
- **增长边**：查询期间由 LLM 根据已有 Episode、Concept 或 Association 新提出的 Association。

## 3. 剧情问题结果

### 3.1 补习部表象与真相

结果：通过。

- `main/31060.json` 提供“成绩不合格、特别学力考试”的表面设定；
- `main/31090.json` 的 Episode #303 精确提供真正目的：让学生退学，因为成员中被认为藏有阻止伊甸条约签订的圣三一叛徒；
- 关键真相排在最终证据第 3 位；
- 本轮没有新增或强化 Association，证明基础混合召回已经足够。

轨迹：`logs/test-next-stage-01.json`

### 3.2 乐园悖论、渚与未花

结果：通过。

- `main/31010.json` / `main/33030.json` 提供乐园悖论；
- `main/31090.json` 提供渚集中嫌疑人、要求找出补习部叛徒的行为；
- `main/32170.json` 的 Episode #1168 提供未花承认政变、把阿里乌斯作为政变工具、让渚下台并由自己成为话事人的证据；
- 三组来源同时进入最终证据；
- 使用的 Association 主要是 generation=0 的 Episode→Concept 语义边，没有保留新增长边。

轨迹：`logs/test-next-stage-02.json`

### 3.3 古圣堂袭击的逆向因果链

初次结果：失败。

- `main/33070.json` 的 Episode #1481 正确命中巡航导弹与预埋炸药判断；
- `main/33100.json` 的 Episode #1595 正确命中阿里乌斯小队发射导弹并夺取条约；
- 但 `main/32170.json` 中未花亲口承认结盟、暗中支援和政变工具的 Episode #1166/#1167/#1168 没有进入 Candidate@100；
- 审计模型错误地用 `main/32140.json` 的 Episode #1040“阿里乌斯欺骗未花并让她安排梓入学”替代“未花主动暗中支援阿里乌斯”。

根因不是 embedding 未召回。针对“哪位茶会高层暗中协助阿里乌斯小队”的子查询中，#1167、#1166、#1168 在融合召回分别位于第 8、11、12 名；它们在多个子查询合并成全局 Candidate@100 时被挤出。

修复：为约束型子问题增加独立的候选保留席位。该机制仅负责让候选进入 LLM 精排，不强制其成为答案，也不修改 confidence 或 generation。

修复后结果：通过。

- 深度模式最终保留 `main/32170.json` 的 #1167；
- 快速模式最终保留更直接的 #1166，其中未花亲口承认“一直在暗中支援阿里乌斯”；
- #1481 和 #1595 同时保留，跨文件证据链闭合；
- 两次修复验证都没有新增或强化 Association，因此收益来自基础召回编排，而非增长边。

轨迹：

- 修复前：`logs/test-next-stage-03.json`
- 修复后深度模式：`logs/test-next-stage-03-fixed.json`
- 修复后快速模式：`logs/test-next-stage-03-fast.json`

## 4. 私人域、公共域与平台隔离

在独立时间戳测试目录中导入：

- Telegram 用户 A 私人事实：“每天晚上十点喜欢喝无糖茉莉茶”；
- 公共事实：“共享验证码是紫色海鸥-728”；
- Discord 用户 B 使用与 A 相同的原生 ID，但平台不同，私库保持为空。

六项检查全部通过：

1. A 能召回自己的私人事实；
2. A 能召回公共事实；
3. B 看不到 A 的私人事实；
4. B 能召回公共事实；
5. 相同原生 ID 在不同平台生成不同私库；
6. 正式剧情数据库路径未发生变化。

## 5. 性能与 Token 结论

复杂剧情问题在 balanced + growth 模式下固定发生 13 次 LLM 调用，实测总耗时为：

| 查询 | LLM 调用 | 总耗时 |
|---|---:|---:|
| 补习部真相 | 13 | 247.8 秒 |
| 乐园悖论 | 13 | 380.3 秒 |
| 古圣堂修复前 | 13 | 392.4 秒 |
| 古圣堂修复后深度模式 | 13 | 467.5 秒 |
| 古圣堂快速模式 | 5 | 125.4 秒 |

快速模式采用 lean 单遍精排并关闭本轮增长，LLM 调用减少 61.5%，总耗时相对同题深度模式减少约 73.2%，同时保留了正确的四组关键证据。

日志表明总耗时几乎全部来自外部 LLM；SQLite 初始化、float32 向量检索和结果格式化不是当前瓶颈。

## 6. 本轮代码变化

- 记忆引擎提示/检索版本升级为 `v3.37_constraint_candidate_reserve`；
- 新增约束型子问题候选保留机制及单元测试；
- 新增 `memory_query.py`，保存单次检索的候选、精排、证据、路径与增长轨迹；
- 新增 `experiments/memory_domain_smoke.py`，可重复验证私人/公共/平台隔离；
- 两个项目的相关单元测试和语法检查均通过。

## 7. 下一阶段建议

1. Telegram 前台使用快速检索，先返回证据支持的答案；
2. 将增长边生成与严格反事实效用审计放入后台队列；
3. 后台增长完成后只更新 SQLite 和索引，不阻塞当前回复；
4. 对同一问题保存“无增长快速结果”和“有增长深度结果”，继续测量增长边是否带来新增直接证据；
5. 为整条前台召回设置总延迟预算，而不是只设置单次 API 超时。

当前最重要的结论是：基础召回的约束候选丢失已经修复，三域隔离也通过真实导入验证；剩余主要工程问题是把高质量但昂贵的增长/审计流程移出同步聊天路径。
